# Independent review of the newly published experiments

Reviewed Git revision: `0dc1335` (17 October 2026). This review does not change experiment code, labels, or saved results. No paid API inference was performed. It inspects the published source and independently rescores saved answers and the policy summary.

## Verdict

Useful exploratory results, but **not a valid completed final experiment package**. The small AVA/AMI agent results are arithmetically reproducible. The implemented safeguard does not beat captured-only accuracy, its quality-only ablation performs better, and the larger agent benchmark has input/label grouping errors. Preserve the useful pilot data; repair the evaluation before spending on a wider model sweep.

## Findings, ordered by impact

### 1. Critical: the larger benchmark merges incompatible evidence

`scripts/build_full_benchmark.py:18-19` retains only the first two `__`-separated ID fields. The subsequent assignments overwrite labels and candidates, but preserve the first captured candidate.

Confirmed collisions:

- `ES2002a__targetA`: both speaking and silent cases merge. The published benchmark has silent labels, captured scores exactly equal to the speaking clip, and FastDVDnet scores exactly equal to the silent clip. This is an invalid before/after comparison.
- `kgVz_AXYvn0__label0`, `kgVz_AXYvn0__label1`, `EEey6Pt0rqI__label0`, and `EEey6Pt0rqI__label1` each merge sigma-15 and sigma-40 captured inputs. The captured/restored candidates are no longer guaranteed to share a parent input.
- AVA restorer names occur in the second ID field, so its two restorers become separate episodes instead of alternatives within one episode. The same source timestamps are repeated.

The existing full Qwen artifact is still `RUNNING`: 9 of 18 generated episodes completed. Fix the episode identity before continuing that run. Some affected episodes have not yet been queried; do not discard unrelated valid raw measurements or automatically rerun all restorations.

### 2. Critical for a method paper: the specified methodological core is absent

`METHOD_PROPOSAL_2026-10-15.md` defines captured temporal support through masked audit passes, withheld captured measurements, timing-disrupted restoration increments, and decision influence. `run_final_experiment.py` instead fits two Ridge regressors to seven aggregate quality/confidence/disagreement features. There are no masked restoration audit passes or withheld-measurement support tests in this script.

This can be reported as a simple exploratory baseline. It is not a completed implementation of the proposed CTS architecture. The implementation's introductory claim of a complete CTS safeguard needs correction before paper use.

### 3. The correction predictor has no positive training examples

The actual development set is 9 pairs from 3 sources, with 441 repeated timestamp opportunities, 3 introduced errors and **zero corrections**. The fitted correction regressor has all-zero coefficients and a zero intercept. Its output is identically zero.

The training/calibration code reuses fitted development predictions and an arbitrary percentile threshold. The comment about capping harm at 2% is not backed by a calibrated statistical risk guarantee. Use separate training/calibration sources or an appropriate source-level cross-fitting procedure, and state the calibration objective precisely. Do not repair the lack of correction examples by selecting favorable examples from the final test set.

### 4. Audio-response features are partly proxies, not measured probes

In `run_final_experiment.py`, AVA uses `mean(abs(restored_prob-captured_prob))*0.15`; the same-video data use the same quantity times 0.2; AMI uses the constant 0.05. These are labelled `audio_alignment_change` and included in the audio-probe ablation. They are not responses to actual audio timing interventions. The temporal-evidence cohort contains a separately measured diagnostic, so the feature has inconsistent meanings across cohorts.

Measure one common intervention on all cohorts or explicitly remove this component. A proxy ablation cannot validate the proposed audiovisual mechanism.

### 5. Source-disjoint fitting is real, but an untouched final test is not established

The fit/test source sets do not overlap. However, the test set is assembled from previously inspected pilot cohorts, including known failure examples. This supports retrospective exploration, not a new blind confirmation test.

The newly uploaded download manifest additionally puts `4ZpjKfu6Cl8` and `ES2002a` in DEVELOPMENT, whereas the final evaluation places both in TEST. The loader does not consume that new manifest and runs on cached pilot JSONs. Reconcile the protocols and freeze one source/participant split before new evaluation. Do not imply that the 25 AVA downloads and 15 AMI meetings were evaluated by these results.

### 6. The model comparison changes the controller between runs

Qwen's completed AVA run declares 8 turns and 768 maximum completion tokens; later models generally use 12 turns and 1,024 tokens, with several different runner hashes, prompts and retry versions. The current controller can explicitly instruct captured-video selection at its deadline. These are controller interventions, not purely model behavior.

The current focused checks pass 15 of 16 tests: the finalization test fails (`8 != 5`). This reflects a changed controller contract that was not reconciled with the test. Fix and freeze one controller, expose the same candidate tools, and rerun the cross-model comparison under the same limits. Report completion rates and failed attempts separately from correctness conditional on completion. Do not infer a model ranking from the present table.

### 7. Quality and coverage reporting require repairs

For mixed policies, `run_final_experiment.py:469` estimates the restored-frame fraction as `mean(final_dec == restored_dec)`. Equal class labels do not reveal which image was selected. This can assign a restoration-quality gain to an output whose evidence origin is unspecified. Multiplying a sparse clip IQA score by that fraction is also not an actual measurement of the selected output sequence.

Track candidate identity per timestamp, generate the selected sequence when it is meaningful, and measure quality on that output; otherwise label this as a surrogate rather than measured output quality. The abstention summary also omits the captured baseline on the same answered timestamps even though per-pair records contain it. Export matched-subset comparisons and risk-coverage curves. Source-level bootstrap is an appropriate direction, but seven previously inspected sources are weak support for a generalization claim.

### 8. The agent results do not test the proposed safeguard end to end

The agent calls inspect detector/quality evidence; they do not call the trained CTS selector. `evaluate_downstream_agent_runs()` reads old saved Qwen outputs, not a with/without-CTS agent experiment. It checks historical run status against `COMPLETE`, whereas the three-video and transfer artifacts use `completed`. Consequently all 20 and 24 historical runs are skipped and the final summary contains only three AVA agent episodes. It also uses defaults that could silently turn missing score fields into zeros.

Use strict versioned result schemas, explicit missingness, and a matched agent comparison with and without the actual safeguard. End-to-end agent improvement cannot be inferred from a separate detector-selection table.

### 9. Data upload and ground-truth scope are overstated

The current Git tree contains `cpu-pilot/data/download_manifest.json`, but no tracked raw dataset assets under that directory. LFS patterns do not publish files unless corresponding pointers are committed. The manifest records 25 AVA source entries and 15 AMI meeting entries; it is a download inventory, not evidence that all those datasets were processed or uploaded.

Several AVA entries name separate-format files (`.f251.webm` and `.f243.webm`). The downloader accepts existing files largely by size and selects the first filename match. This does not verify a merged video-plus-audio stream. Without those assets, I cannot establish their integrity. Probe required streams, source-time correspondence, duration, synchronization and hashes before running them.

AMI's originating artifact explicitly describes transcript-segment proxy labels and added Gaussian noise sigma 40. The aggregate loader calls its degradation `Meeting-Capture`, obscuring the synthetic corruption. Preserve that provenance and validate dense labels before making speaker-attribution claims. The task is per-face speaking activity, not named-speaker/utterance attribution or demonstrated agent actions.

### 10. Small implementation defect in credential fallback

The provider constructs Authorization headers before its retry loop. On 401 it changes `self.key`, but does not rebuild those headers. The backup key therefore is not actually sent on subsequent attempts. This is an execution issue, not evidence of model accuracy; repair and unit-test it before a longer run.

## What to keep, recompute, and rerun

| Action | Scope | Why |
|---|---|---|
| Keep | Original per-case restoration arrays, official/proxy label provenance, complete small-run traces, all failures | Useful evidence; independent arithmetic checks passed |
| Rebuild locally first | Unified episode IDs, candidate-parent checks, labels, aggregation, quality-origin accounting, cohort reports | These are data/evaluation defects; no API spend is required to diagnose them |
| Treat as exploratory | Existing policy results and source-disjoint pilot split | The numbers reproduce, but neither method implementation nor test independence supports final claims |
| Implement and validate | Actual proposed temporal-support core, or explicitly revise the method claim | Two Ridge models over familiar aggregates are not the stated architecture |
| Retrain/calibrate | Source-disjoint development data containing a meaningful range of harm, correction and unchanged cases | Current correction estimator cannot learn a benefit |
| Rerun under one frozen controller | Cross-model AVA and AMI comparison, plus failed GLM AVA episodes | Current model comparisons use changing protocols and retries |
| Run fresh confirmation | New untouched AVA/AMI sources from one reconciled manifest; additional planned datasets only after adapters pass validation | More calls on old clips are not independent confirmation |
| Run actual end-to-end comparison | Same agent, tasks, tools and budget, with/without safeguard | Current Qwen runs do not evaluate the trained safeguard |

Do not launch every model on every download yet. First repair the benchmark and demonstrate the true method on a small development batch. Freeze it, then spend on the fresh-source confirmation experiment. A negative final result is acceptable; changing evaluation or evidence to force success is not.

## Review limits

This is a code/data audit and offline rescore, not a new media annotation exercise or a literature novelty certification. Raw new downloads were not available in the Git tree, so their audiovisual integrity was not verified. No paper text was changed and no experiment outputs were overwritten.
